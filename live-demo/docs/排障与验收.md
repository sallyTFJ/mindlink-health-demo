# 排障与验收

## 先离线，再硬件

1. CHECK_INSTALL.cmd 全部通过；离线样例得分与预期一致。这只验证安装和计算，不证明硬件稳定或模型准确。
2. 默认 disabled 启动工作台，页面正常、无设备时状态 invalid，不能有假的实时分数。
3. 选择 serial 和实际 COM；确认设备已配对、打开正确串口，RAW 总数持续增长。等待连续 5 秒良好质量窗口，再等待一个 5–10 秒解码周期。
4. 戴上设备连续观察 10 分钟，记录断流次数；移动电极/短暂断开后，应显示无效并在恢复后重新积累窗口，不能冻结旧分数冒充实时。
5. 开启 HeartCast，验证真实心率；停止广播后 15 秒应无效。拔设备、休眠恢复、重启也应逐项验收。
6. 队友持新令牌读取状态；无令牌应 401。记录 EEG/心率各自时间，确认缺失状态能到后端。

## 常见情况

|现象|检查|
|---|---|
|9080 被占用|关闭本包旧窗口，或修改 config.json 的 port；不是让所有 Python/心率服务退出|
|COM 拒绝访问|同一 COM 仅一个采集进程；旧 8876 正在采集时，选 http 复用或退出旧采集后再 serial|
|RAW 一直 0|检查真实 COM、设备电量和连接、蓝牙串口方向/状态；浏览器 HTTP 200 只证明页面接口活着|
|有 RAW 没脑状态|看 quality、窗口连续性和 reason；接触不良仍显示噪声，但不伪造有效模型结果|
|一戴上就断流|可能是接触、运动、设备或无线链路；先看 RAW 是否仍增长，再看质量，不能仅凭现象断定佩戴问题|
|8 秒后重连|连续无 RAW 会重开同一串口；若 Windows 驱动调用本身卡住，线程不能保证强制解除，需要退出采集或重连设备|
|HeartCast 找不到|手机/手表应用是否在广播；Windows 蓝牙是否开启；是否被另一个接收器占用；名称不符可用 --name|
|心率有值但无效|接触标记、事件时间或 15 秒新鲜度未通过；旧 JSONL 不能让数据一直有效|
|DLL 加载错误|先用 tools/Microsoft_VC_Runtime_x64.exe 安装微软 VC x64 运行库，再检查；需 Windows x64，不能在 Mac 直接执行 runtime/python.exe|
|页面仍旧|Ctrl+F5，确认访问的是本包端口；多份文件夹会各自保存配置与令牌|

佩戴建议：按设备说明放置前额与参考电极，清理皮肤油污，确保贴合但不过紧，减少说话、咬牙和头部运动造成的肌电；先做短时静坐基线。不要通过降低质量标准把噪声当成专注或情绪变化。

蓝牙按名称启动的单行命令（在包根目录）：

```text
runtime\python.exe heartcast.py --name HeartCast
```

本次软件检查记录见 evidence。实际 Windows 启动、现场串口/BLE 和人体任务效果须由接收方按上述步骤验证；本包没有声称已完成这些测试。
