# 模块与模型说明

## 一张图理解流程

脑电设备 → COM 串口 → ThinkGear 校验与 RAW 解析 → 5 秒连续有效窗口 → 本机 CPU 解码 → JSON / 网页

手表 → 手机 HeartCast / 标准 BLE 心率广播 → heartcast.py → 心率 JSONL → JSON / 网页

两路数据汇合到 `GET /api/state`，供新项目的后端或决策模型读取。这个包不替后端决定是否说话，也不生成聊天文本。

## 文件各自做什么

|目录或文件|作用|
|---|---|
|server.py、app/|9080 工作台、输入采集、状态过期判断、显示与接口|
|eeg_decoder/|模型 SDK、预处理、ThinkGear 协议解析；可独立导入|
|models/|20 个 ONNX 模型：5 折 × 2 个任务 × 2 个种子；包含原始哈希清单|
|runtime/|Windows x64 Python 与 CPU 推理依赖，无需另装 Python|
|heartcast.py|接收标准 BLE 心率特征值，保存为 JSONL|
|web/|原始波形、RMS 包络、频段热图、二维研究分数与心率页面|
|model_api.py|可选的独立 8881 模型服务，给已有采集程序使用|
|tools/client_example.py|队友读取状态或提交 5 秒数据的标准库示例|
|research/source/|训练源码、PyTorch 检查点、冻结协议和评估结果|
|examples/|公共数据离线窗口及预期输出，用于安装验收|
|evidence/|历史模型评估、ONNX 对齐记录及本次交付检查|
|data/|运行后生成心率 JSONL 和 events.sqlite3；数据库记录解码/心率事件，不是连续原始 EEG 录制|
|private/|运行后生成本机 API 令牌；发布包中为空|

## EEG 模型

原研究模型采用 EEGNet 骨干，结合 90 维频谱特征分支和动态时间汇聚。它是小型 EEG 研究模型，不是聊天 LoRA。保留原模型版本 ID 是为了追溯权重，不代表依赖旧项目或旧云服务。

输入是 Fp1 单通道 5 秒数据。SDK 接受 128、250、256、512 Hz；原始 NeuroSky counts 只接受 512 Hz，并进行一次单位换算。预处理重采样至 128 Hz、1–40 Hz 带通、舍弃开始 1 秒，形成 4 秒/512 点输入。不能把其他通道、多通道数组或厂商 Attention 指标直接当 RAW 输入。

默认部署使用第 0 折，每个任务两个种子聚合；其余折用于研究检查，不等于现场自动做五折平均。专注输出 0–100 是任务代理分数，情绪效价 -1–1 表示研究标签的负向到正向，不代表已识别具体情绪类别。

注意：原注意任务标签来自冥想数据中探针前的自报走神程度；效价来自 FACED 影片主观评分。它们不是办公状态标签，迁移到消费级设备和现场任务需要重新验证。

## 实际效果：保留不足，不包装为高准确率

历史记录为重复使用开发数据的探索性交叉验证，不是独立外部测试。

|任务|评估范围|记录中的主要结果|解释|
|---|---|---|---|
|专注代理|20 人、800 试次、2397 窗口；19 人具备两类标签|个体平衡准确率平均 51.57%，95% CI 47.78–55.53%；先验基线 50%|不足以证明可靠优于基线；汇总全部试次的平衡准确率为 45.89%|
|情绪效价|103 人、2884 试次、23063 窗口|MAE 0.4905；先验基线 0.4845，误差越低越好|未优于该基线；不能宣称准确情绪识别|

依据：`evidence/eeg_evaluation.json`。代码能运行、ONNX 与 PyTorch 对齐、窗口 valid，都不等于心理识别有效。

## 实时显示与有效性

- 波形和 250ms RMS 包络保留接触不良时收到的真实噪声；实际断流不插值、不生成假波形。
- 频段热图是最近数据的相对功率随时间变化，不是头皮地形图；接触质量另行标注。
- 只有符合质量与连续性要求的窗口才送解码。收到 RAW 和能得到有效解码是两回事。
- 每 5–10 秒更新脑状态；二维图以约 10 秒时间常数平滑。`display_xy` 只用于显示，原始分数仍保留，断流/会话切换清空平滑状态。
- 心率只能作为辅助线索；`ecg.valid=false` 明示尚无心电波形。

如要做现场闭环，建议先完成连续采集、断线恢复和真实任务标注，再评估分数与任务的关系，不能把分数高低直接等同于人的感受或能力。
